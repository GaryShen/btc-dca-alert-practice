【這個工具要解決什麼】
我想知道：每週一定投 BTC，如果「跌比較多時多投一點」，投入金額和平均成本會怎麼變。

【使用者要填什麼】
開始日期（預設 2022-01-03）、結束日期（預設資料最後一天：有抓到新價格就是最新的那個週一，抓不到就是 2026-09-28）、每週金額（預設 100 美元）、加碼條件（選一個指標＋「大於」或「小於」＋門檻；預設「距最高點跌幅 大於 30%」）、加碼倍數（預設 2 倍）。

【規則】
1. 每週一買一次，用當週價格；只算開始到結束日期之間的週，頭尾都算。
2. 每週算出所選指標的值。值「大於」（或選「小於」）門檻，就投「每週金額 × 加碼倍數」；不然就投「每週金額」。剛好等於門檻不算。
3. 指標那週「資料不足」，就投「每週金額」，不加碼。
4. 預設指標「距最高點跌幅」：最高點＝資料中截至當週的最高價，開始日期之前的價格也要算進去；跌幅＝（最高點 − 當週價格）÷ 最高點。
5. 平均成本＝總投入 ÷ 買到的 BTC 總數。
6. 不算手續費。
7. 指標怎麼算見【指標插件】；換指標只換加碼條件，其他規則不變。

【要看到什麼】
兩條規則並排：只定期定額／加碼規則。
每條都要有：總投入、買到的 BTC、平均成本、加碼次數、市值。加碼次數＝實際投入比每週金額多的週數（倍數設 1 就是 0 次）；市值用所選期間最後一筆價格算。
顯示實際算了哪幾週、共幾週；下面一張逐週明細：日期、價格、所選指標的值（資料不足就寫「資料不足」；距最高點跌幅另外附上最高點）、兩條規則各投多少。
結果旁邊寫：「用當天均價回算・沒算手續費・實際不一定買得到這個價」，還有「過去結果不代表未來，也不是投資建議」。
所選指標有「資料不足」的週，結果旁邊寫出共有幾週資料不足（那幾週照每週金額投）。用到外部資料的指標，選單旁邊標出資料來源。
填錯（包括門檻超出所選指標可填的範圍），或那段時間沒有價格資料，要提醒我，不要留著上一次的結果。

【資料】
1. 內建資料：data/btc_weekly.csv（欄位：date, price_usd），2017-01-02～2026-09-28。這個檔不改，留著當離線備用。
2. 新價格：打開網頁時，從 Kraken 的公開 API 抓每日價格（免費、不用金鑰、不用登入）：
   https://api.kraken.com/0/public/OHLC?pair=XBTUSD&interval=1440
   每一筆的第 6 個值是當天成交均價（vwap）。只取週一、四捨五入到整數，日期以 UTC 為準。
3. 接法：2026-09-28 以前一律用內建資料；2026-09-28 之後的週才用抓到的價格，接在內建資料後面。
4. 只用已經過完的日子：今天如果是週一，今天這筆還沒結束，先不用。
5. 抓不到（沒網路、10 秒內沒回應、回來的內容看不懂、或沒有 2026-09-28 之後的週一）：畫面明講「抓不到最新價格，改用內建資料（到 2026-09-28）」，照樣可以算，不要默默用舊結果，也不要留空白。
6. 畫面上要標出：價格資料到哪一天；2026-09-28 之後的價格來源是 Kraken。
7. 驗收模式（#test-w1）照舊只用內建／合成資料，不上網抓（指標要用的網路資料也不抓）。

【指標插件】
1. 指標放在 indicators/ 資料夾，一個指標一個檔案。每個檔案寫清楚：
   - 名稱（選單上顯示的字）
   - 單位（例如 %）
   - 門檻可以填的範圍（例如 0–100 的整數）
   - 需要幾週資料：截至當週（含當週）至少要有幾週價格才算得出來
   - 怎麼算：只能用截至當週的資料，不能用到之後的價格
   - 資料不夠時回「資料不足」
   - 資料來源（用到外部資料的指標才寫）
2. indicators/清單.js 一行一個檔名。網頁照清單載入，清單有幾個，選單就有幾個選項（雙擊打開的網頁看不到資料夾裡有哪些檔案，所以要清單）。
3. 需要網路資料的指標，自己在檔案裡寫怎麼抓，網頁不用為它改；但什麼時候抓由網頁決定：只在正式畫面抓，驗收模式不抓。還在抓時，選單上標「準備中」、先不能算；10 秒內沒回應、或回來的內容看不懂，就算抓不到；抓到的資料沒有某個週一，那週就是「資料不足」。
4. 第一個插件是 indicators/drawdown.js「距最高點跌幅」（單位 %，門檻 0–100 整數，需要 1 週資料），算出來的結果要跟改成插件之前一模一樣。
5. 一個指標出錯，其他指標照常能選、能算，畫面要寫出是哪個指標出錯：
   - 檔案載入失敗（檔名寫錯、檔案壞掉、抓不到網路資料）：選單上那一項標「出錯」、不能選。
   - 算到一半出錯：這次不給結果（不給一半，也不留上一次的結果），寫出「哪個指標、出了什麼錯」；換別的指標照常能算。
6. 第二個插件是 indicators/fear_greed.js「恐懼貪婪指數」：
   - 資料從 alternative.me 的免費 API 抓（不用金鑰）：https://api.alternative.me/fng/?limit=0
   - 取每週一的值（0–100，沒有單位），日期以 UTC 為準；門檻 0–100 整數，需要 1 週資料。
   - 2018-02-01 以前沒有資料，API 偶爾也會缺某一天：那幾週是「資料不足」，照每週金額投，不能當成 0。
   - 資料來源標「alternative.me」。

【雲端存檔】
1. 存什麼：只存我填的條件——開始日期、結束日期、每週金額、指標、大於或小於、門檻、加碼倍數。計算結果不存，打開網頁時照存好的條件重算。
2. 存在哪：Supabase 資料庫。一個帳號只存一份，再存就蓋掉舊的。
3. 誰能讀、能改：要登入才能存、才能讀；每個人只讀得到、改得到自己那一份。這由資料庫的權限規則（RLS）擋，不能只靠網頁擋——就算有人改了網頁，也拿不到、改不到別人的。
4. 帳號：只有我一個人用，不開放註冊；帳號我自己在 Supabase 後台建。網頁上用 email＋密碼登入（這是登入 Supabase，跟交易所無關）。
5. 金鑰：網頁裡只能放 Supabase 的網址和 publishable key；secret key 不能放進網頁，也不能放進 repo。
6. 什麼時候存：按「存到雲端」才存，不要每算一次就自動存。填的條件沒通過檢查（同【要看到什麼】的填錯規則），就不存，提醒我哪一項錯。
7. 什麼時候讀回：登入後，等價格和指標的資料都載入好（指標不再是「準備中」），才把存好的條件填回畫面，再照它重算。還沒存過就維持預設值。
8. 讀回來的檢查：跟手動填的用同一套檢查。哪一項沒通過（例如存的指標現在「出錯」或不在清單上、門檻超出那個指標可填的範圍），就那一項用預設值，畫面寫出「哪一項讀回來不對、改用預設值」；其他項照存的值。
9. 沒登入、沒網路、Supabase 連不上：網頁照樣能開、能算（同【資料】的規則），只是不能存、不能讀回。畫面要講清楚：
   - 現在有沒有登入（登入的話顯示 email）；
   - 存好了沒有：已存到雲端／畫面上的條件改過、還沒存／存失敗（寫出原因）。
   - 登入失敗、讀回失敗也要寫出來，不要默默用預設值。
10. 驗收模式（#test-w1）照舊：不連資料庫、不登入、不讀回存好的條件，結果一樣。

【上線與通知】
1. 上線：網站放在 Vercel，接 GitHub，推上 GitHub 就自動更新。雙擊 index.html 照舊能用（同【開啟方式】），驗收模式（#test-w1）照舊。
2. 每天檢查：
   - Vercel 排程每天叫排程程式起來一次，設在台灣時間 9:00；免費方案實際會在 9:00～10:00 之間的某個時間。
   - 條件：讀 Supabase 裡我那個帳號存的那份（同【雲端存檔】），用其中的指標、大於或小於、門檻、每週金額、加碼倍數；開始、結束日期用不到。讀回來的檢查同【雲端存檔】8：哪一項不對，那一項用預設值，通知裡寫出來。還沒存過就全用預設值。
   - 價格：先照【資料】接好每週資料（內建資料＋Kraken 週一），再把「最新一筆已經過完的每日均價」接在最後面當最後一筆。這筆本身就是週一（已經在每週資料裡）就不重複接。Kraken 每日價格的日期照【資料】以 UTC 為準，「已經過完」＝那個 UTC 日已經結束；台灣 9～10 點檢查時，就是前一天那筆。
   - 指標：用 indicators/ 同一份檔案，對最後一筆算，只能用截至那筆的資料；指標照那筆的日期取值（恐懼貪婪指數取那一天的值，沒有就是「資料不足」）。排程每次都抓指標要的網路資料。
   - 算法跟網頁同一套：排程程式和網頁共用同一份計算和指標檔案，不能另外抄一份。為了共用而把計算從 index.html 搬出來時，網頁結果要一模一樣（#test-w1 照樣全部相符、2026-01-19～2026-02-09 案例照樣 $600）。
   - 條件有沒有成立：同【規則】2、3，最後一筆的指標值「大於」（或「小於」）門檻才成立，剛好等於不算；「資料不足」＝沒成立、不加碼。
   - 這週該投多少：成立＝每週金額 × 加碼倍數；沒成立（含資料不足）＝每週金額。
   - 日期：檢查日、「週一」、「同一天」、「這週」一律用台灣時間（UTC+8）。
3. 什麼時候通知：傳到我的 Telegram，一天最多一則。照下面順序，符合哪一條就照那一條，後面不再看：
   1. 今天（台灣時間）已經有成功檢查的紀錄：不重算、不重送、不再記一筆，直接回「今天已檢查過」。一天只能有一筆，由資料庫擋，不能只靠程式擋。
   2. 第一次檢查（之前沒有任何成功檢查的紀錄）：傳一則「開始幫你看了」，附上今天的狀況。第一次剛好是週一也只傳這一則（裡面已經寫這週該投多少）。
   3. 週一：固定傳一則，寫這週該投多少。
   4. 其他日子：上一次成功檢查「沒成立」（含資料不足）、今天成立，才傳一則。上一次已經成立、今天也成立，不傳。
   5. 其他情況不傳，但照樣記紀錄。
4. 通知的內容：
   - 第一行寫是哪一種：開始幫你看了／週一／條件成立了。
   - 檢查日（台灣時間）；用的是哪一天的價格、價格多少。
   - 條件（例：距最高點跌幅 大於 30%）、指標的值（距最高點跌幅另外附上最高點；資料不足就寫「資料不足，不加碼」）。
   - 條件有沒有成立、這週該投多少。
   - 有讀回來不對、改用預設值的項目，寫出是哪一項。
   - 最後一行固定寫「這是你自己設的條件到了，不是買賣建議。」
5. 抓不到資料：
   - Kraken 價格、指標要的網路資料、Supabase 存好的條件，任一樣抓不到（10 秒沒回應、回來的內容看不懂、Kraken 沒有前一個 UTC 日那筆）：這次就算失敗。不能當成「條件沒成立」，不改用內建資料，不記紀錄（不算今天檢查過），不傳通知；下一次叫起來照常重來。
   - 指標檔案載入失敗、算到一半出錯，也算這次失敗。
   - 指標那天「資料不足」不算失敗：照【規則】3 不加碼，通知裡寫出來。
6. 檢查紀錄：
   - 每次成功檢查記一筆到 Supabase：檢查日（台灣時間）、檢查時間、用哪一天的價格和價格多少、指標名稱和值（或「資料不足」）、條件有沒有成立、這週該投多少、有沒有傳通知（傳了哪一種／沒傳／傳送失敗＋原因）。
   - 順序：先記紀錄，再傳通知，再把通知結果補記上去。記紀錄失敗＝這次失敗，不傳通知（這樣一天最多一則）。Telegram 傳送失敗：紀錄照留，寫「通知傳送失敗」和原因，當天不重送。
   - 誰能讀、能寫：紀錄只有排程程式能寫；網頁登入後只讀得到自己的紀錄，不能改、不能刪。由資料庫的權限規則（RLS）擋（同【雲端存檔】3）。
   - 網頁登入後顯示「最後一次成功檢查」的時間（台灣時間）和結果（指標的值、條件有沒有成立、這週該投多少、有沒有傳通知）。離現在超過 48 小時、或從來沒有成功檢查過，用醒目的字寫「超過兩天沒有成功檢查，排程可能沒在跑」。讀紀錄失敗也要寫出來。沒登入就寫「登入後才看得到檢查紀錄」。

【開啟方式】
雙擊 index.html 就能用，不用另外安裝任何東西。沒有網路也能開、能算（用內建資料）；沒登入也能算，只是不能存到雲端。上線的網站（Vercel）功能一樣。

不要下單、不要登入或連接交易所帳戶（只讀 Kraken 公開的價格；唯一的登入是【雲端存檔】的 Supabase）、不要給投資建議、不要說哪條規則比較好。通知只講我自己設的條件有沒有到、這週照規則該投多少，不寫該買或該賣。
