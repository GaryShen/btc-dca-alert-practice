# W1 指令包：第一版怎麼做出來？

這週的流程：**寫需求單 → Claude Design 畫畫面 → Claude Code 做出來 → 在網頁上跟標準答案對一次**。

先照 [開工檢查](../docs/開工檢查.md) 準備好資料夾：想從頭跟著做，下載 `v0.0`（價格資料和跟做文件，還沒有網頁）；只想看成品，下載 `v0.1`。

## 1. 需求單（可以照抄，也可以改成你自己的規則）

需求單就是軟體業說的 PRD（產品需求文件）的精簡版，用白話寫就好：使用者要填什麼、怎麼算、要看到什麼、不要做什麼。跟做時，下面這一步會請 Code 把它存成 `docs/需求單.md`：之後 Design 畫畫面、Code 寫程式都照這一份，畫面跟需求不一樣時以它為準，要改規則也只改這一份。改了規則，標準答案就要重算，不能沿用本集的答案。

```text
【這個工具要解決什麼】
我想知道：每週一定投 BTC，如果「跌比較多時多投一點」，投入金額和平均成本會怎麼變。

【使用者要填什麼】
開始日期（預設 2022-01-03）、結束日期（預設資料最後一天 2026-09-28）、每週金額（預設 100 美元）、跌幅門檻（預設 30%）、加碼倍數（預設 2 倍）。

【規則】
1. 每週一買一次，用當週價格；只算開始到結束日期之間的週，頭尾都算。
2. 最高點＝資料中截至當週的最高價，開始日期之前的價格也要算進去。
3. 跌幅＝（最高點 − 當週價格）÷ 最高點。
4. 跌幅「超過」門檻，就投「每週金額 × 加碼倍數」；沒超過就投「每週金額」。剛好等於門檻不算超過。
5. 平均成本＝總投入 ÷ 買到的 BTC 總數。
6. 不算手續費。

【要看到什麼】
兩條規則並排：只定期定額／加碼規則。
每條都要有：總投入、買到的 BTC、平均成本、加碼次數、市值。加碼次數＝實際投入比每週金額多的週數（倍數設 1 就是 0 次）；市值用所選期間最後一筆價格算。
顯示實際算了哪幾週、共幾週；下面一張逐週明細：日期、價格、最高點、跌幅、兩條規則各投多少。
結果旁邊寫：「用當天均價回算・沒算手續費・實際不一定買得到這個價」，還有「過去結果不代表未來，也不是投資建議」。
填錯，或那段時間沒有價格資料，要提醒我，不要留著上一次的結果。

【資料】
用資料夾裡的 data/btc_weekly.csv（欄位：date, price_usd），不要上網抓。

【開啟方式】
雙擊 index.html 就能用，不用另外安裝任何東西。

【不要做】
不要下單、不要連交易所、不要給投資建議、不要說哪條規則比較好。
```

在 Claude 桌面 App 的 **Code** 分頁選 Local、選你的練習資料夾，貼上這段，再接上面的需求單：

```text
請把下面這份需求單原文存成 docs/需求單.md，資料夾不存在就建立。
確認 data/btc_weekly.csv 存在，讀取欄位、日期範圍和筆數給我看；不要修改價格檔，也先不要製作網頁。

（貼上需求單）
```

## 2. 用 Claude Design 畫畫面（在 Code 裡打 /design）

在同一個 Code 對話輸入下面這段。開頭的 `/design` 會叫出 Claude Design；需求單已經存在 `docs/需求單.md`，不用再貼全文。

```text
/design 照 docs/需求單.md 設計一個單頁網頁的畫面：上面是五個輸入欄位（開始日期、結束日期、每週金額、跌幅門檻、加碼倍數）和「計算」按鈕，中間兩張結果卡並排，下面是逐週明細表。
這一步只畫設計稿，先不要寫程式、不要建立檔案；需求單裡的【資料】和【開啟方式】是之後做網頁時才用。
畫面簡單清楚就好，電腦和手機都要能看。需求單沒寫的功能不要加。
數字先用示意，標「示意」；保留實際期間、週數、回算說明和錯誤提示的位置。
```

Code 會回一個設計稿連結，用瀏覽器打開。它可能一次畫好幾版，挑最符合需求單的那一版，記下名稱。`/design` 沒出現的話，先把 Claude 桌面 App 更新到最新版。

畫面出來後核對：五個輸入欄位、兩張結果卡、逐週明細、實際期間和回算說明。

- 需求單寫了、它沒照做：回 Code 指出是哪一條，請它只修那個地方（也可以直接在畫布上改）。
- 需求單本來就沒寫清楚：先改 `docs/需求單.md`，再請它照新版重畫；之後做網頁也用這一份。
- 全部符合：直接往下，不用刻意找錯。

## 3. 照設計稿做出來

畫面確認好，回到同一個 Code 對話，貼下面這段（第一行的〇〇換成你挑的那一版名稱；後面是給 AI 的施工條件，不用寫進需求單）：

```text
照剛才設計稿裡「〇〇」那一版，做出真的網頁。
規則以 docs/需求單.md 為準；設計稿跟需求單不一樣的地方，以需求單為準。設計稿上的數字只是示意，要換成實際算出來的結果。
做成可以直接雙擊打開的單頁 index.html：
- 把 data/btc_weekly.csv 的完整資料內嵌進網頁，原檔保留；不要在網頁打開後用 fetch 讀檔，也不要上網抓價格。
- 不需要伺服器、不用安裝套件、不連外部網路資源。
- 門檻只接受 0–100 的整數；每週金額要大於 0；加碼倍數至少 1。
- 另外做一個驗收模式：網址後面加 #test-w1 就切過去，畫面標「合成資料」。用跟正式畫面同一個計算函式，算四週價格 100、80、70、60（每週 100、門檻 30%、2 倍），列出每週的預期投入（100、100、100、200）和實際投入。
- 合成資料用 docs/W1_標準答案.md 給的四個日期（2026-01-05～2026-01-26），這四筆就是完整歷史，最高點從 100 起算；不沿用正式畫面的日期範圍或最高點。標準答案〈B 補充〉的五個兩週案例也列在驗收模式，一樣用同一個計算函式。
- 驗收模式不要另外寫一份算法，也不要動到真實資料；要有回到正式畫面的按鈕。
先列出你的做法和要建立的檔案，我確認後再開始寫。
做好後告訴我怎麼打開。驗收我會自己在網頁上對，不要只在對話裡算給我看就說通過。
```

看它的計畫有沒有：五個欄位、資料內嵌、起訖區間、開始日期之前的最高點、驗收模式跟正式畫面共用同一個計算。都有再請它開始做。

帳號用不了 Design（打 `/design` 沒反應），但 Code 可以用而且還有額度：跳過第 2 節，把上面這段第一行改成「照 docs/需求單.md 做出網頁」，直接交給 Code。Design 和 Code 共用額度，用完了要等重設，換工具不會多出額度。[官方說明](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)

## 4. 自己在網頁上驗收

對照 [W1 標準答案](../docs/W1_標準答案.md)：

1. 雙擊 `index.html`，用預設日期 2022-01-03～2026-09-28 計算 C：248 週，兩邊總投入 $24,800／$39,000。
2. 改成 2026-01-19～2026-02-09，其他維持每週 100、門檻 30%、2 倍。A：加碼規則四週投入 100、100、200、200，總投入 $600、平均成本 $78,229.20。要看網頁上的明細，不能只看 AI 的回答。
3. 網址最後加上 `#test-w1`，進入驗收模式（標「合成資料」）。B：四週投入應該是 100、100、100、200，總投入 $500。
4. 回到正式畫面，重算 A，確認還是 $600。

B 沒過（第 3 週投了 200）的話，先別猜原因，把這段交給 Code：

```text
驗收模式第 3 週：最高點 100、價格 70、門檻 30%，跌幅剛好 30%。需求單寫「剛好等於門檻不算超過」，應該投 100，網頁卻投了 200（總投入預期 500，實際 600）。
請先找出正式畫面用的計算函式是哪裡判斷錯、為什麼，用白話說明給我看；再修正那個函式，不要只為 30% 寫特例。
改完重跑驗收模式，再回正式畫面重算 2026-01-19 到 2026-02-09，確認還是 $600。
```

原因可能是 `>` 寫成 `>=`、最高點帶錯、門檻單位弄錯，也可能是小數比較的誤差（電腦算 `1 − 70/100` 會得到 0.30000000000000004）。如果查出是小數誤差，請它改用整數比較「（最高點 − 當週價格）× 100 > 最高點 × 門檻」；不要先四捨五入再比。

其他地方對不上，就把「輸入、網頁算出來的、標準答案」三樣告訴 AI，請它修原本的計算再重跑。不要請它把標準答案改成程式現在的結果。

這個驗收現在是手動點、手動對；到 W6，我們會把它變成每次改完程式就自動跑。

這版用當天均價回算、沒算手續費，實際不一定買得到這個價；過去結果不代表未來，也不是投資建議。
