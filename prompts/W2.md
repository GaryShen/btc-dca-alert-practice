# W2 指令包：改壞了怎麼辦？

這週的流程：**先存檔 → 改 → 看它改了哪裡、驗證 → 不對就退回 → 寫 CLAUDE.md → 放上 GitHub**。

一句話：**改之前先存檔，改之後驗證，不對就退回。**

開始前先照 [開工檢查〈W2〉](../docs/開工檢查.md#w2改壞了怎麼辦) 準備好：上週的練習資料夾（沒跟到的人下載 `v0.1`）、GitHub 帳號、GitHub Desktop、電腦上的 Git。

## 1. 開始存檔

在 Claude 桌面 App 的 Code 分頁，選你的練習資料夾，貼：

```text
幫我在這個資料夾開始用 Git 存檔：
0. 先確認這台電腦有沒有 Git（例如跑 git --version）。沒有的話先停下來，告訴我怎麼裝，不要自己安裝。
1. 如果還不是 Git 專案，就初始化一個；加一個 .gitignore，排除 .DS_Store 這類系統檔。
2. 先列出要存進去的檔案給我看，確認 index.html、data/btc_weekly.csv、docs/ 都在。
3. 把現在這版存成第一個存檔，存檔說明寫「v0.1：W1 驗收通過」。
不要改任何檔案內容，也先不要上傳到 GitHub。
如果 Git 還沒設定名字和 email，先停下來告訴我，不要自己填。
```

它要執行 `git` 指令前會先問你，看一下是 `git init`、`git add`、`git commit` 這類存檔指令，再按允許。

它說找不到 Git？照 [開工檢查〈W2〉第 4 步](../docs/開工檢查.md#w2改壞了怎麼辦) 裝好，再貼一次同一段。Mac 如果跳出「安裝命令列開發者工具」的視窗，按 **安裝**，等它裝完再叫 Code 重試。

## 3. 故意改壞（影片示範用）

```text
跌到三成就加碼兩倍，只改計算就好。需求單和驗收的預期答案都不要動，直接改。
```

我們的需求單寫的是跌「超過」門檻才加碼、剛好等於不算；這句口語會把規則改掉。

為什麼要交代「需求單和驗收的預期答案都不要動」？現在的 AI 常會順手把需求單、驗收答案一起改成新規則，驗收就永遠全對，看不出改壞了。這是示範才這樣交代；平常真的要改規則，照 CLAUDE.md 的做法：先改需求單和標準答案，你確認後才改程式。

改完照下面兩項驗收：

1. **真實價格案例**：正式畫面算 2026-01-19～2026-02-09（每週 100、門檻 30、2 倍），加碼規則總投入 **$600**。改壞前後都一樣，真實資料看不出來。
2. **合成驗收案例（測試題）**：網址最後加 `#test-w1`。正確答案是總投入 $500；改壞後應該是 **「有不符：6 / 12」**，剛好 30% 那週投了 200、總投入變 $600。如果顯示全部相符，看一下第 3 週的「預期」是不是被改成 200 了——那是連考卷答案一起改掉。

## 4. 看它改了哪裡

點 Code 對話框旁的 `+N −M`（或視窗上方的 **Changes**），左邊是改到的檔案，右邊紅色是刪掉、綠色是加上（顏色不代表對錯）。這次會看到 `>`（超過）變成 `>=`（達到或超過）。也可以問：

```text
這次改了哪些檔案、哪幾行？
```

## 5. 退回上一個存檔

```text
把這次還沒存檔的修改全部退回，回到上一個存檔。
退回前先列出會被退回的檔案，已暫存的和新增的檔案也要列出來；不要動已經存好的存檔紀錄。
```

退回後重新整理網頁：`#test-w1` 要回到「全部相符 12 / 12」（測試題回到 $500），正式畫面的真實價格案例還是 $600。再列一次存檔紀錄：還是只有一個——改壞的版本沒有被存進去。

## 6. 建立 CLAUDE.md

```text
照下面的內容，在資料夾最外層建立 CLAUDE.md，內容不要改。
建好之後存一個新的存檔，說明寫「加上 CLAUDE.md 工作守則」，再列出存檔紀錄。

（把 CLAUDE.md 範本整份貼在這裡）
```

範本在 repo 根目錄的 [`CLAUDE.md`](../CLAUDE.md)。你可以改成自己的規則，但要寫得具體：哪個檔案是規則、哪些東西不能動、改完怎麼驗收、什麼時候才存檔。

CLAUDE.md 會在**每次開新對話、開工時**先讀。要看它能不能照約定接手，開一個新對話（側邊欄 **＋ New session**，分支名稱旁的 worktree 不要勾），再貼一次第 3 步那句話：它應該先停下來問你要不要改需求單。就算它沒問、直接改了，也照第 4、5 步看修改、退回就好——CLAUDE.md 是提醒，不是鎖。

## 7. 放上 GitHub（GitHub Desktop）

1. 打開 GitHub Desktop → **File → Add Local Repository**（第一次打開、還在「Let's get started!」歡迎畫面的話，選 **Add an Existing Repository from your Local Drive…**）→ **Choose…** 選練習資料夾 → **Add Repository**。左邊 **History** 看得到剛才的存檔。
2. 按 **Publish repository**，名稱可以保留；**勾「Keep this code private」**（練習用，只有你看得到）→ **Publish Repository**。
3. **Repository → View on GitHub**：檔案和存檔都在。
4. 之後每次存檔完，在 GitHub Desktop 按 **Push origin** 上傳。

為什麼用 GitHub Desktop？它是圖形介面，登入、發布、上傳都是按按鈕，第一次比較容易跟著做。想讓 Code 直接上傳也可以，但第一次登入的設定每台電腦不太一樣，這系列先不走這條。
